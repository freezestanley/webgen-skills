# 基建与生成（Setup & Generation）

| 命令 | 作用 |
|------|------|
| `init` | 在项目目录中初始化 Impeccable 配置与基础工程结构 |
| `teach` | 注入产品上下文：生成/设置 PRODUCT.md 和 DESIGN.md 两份核心文档 |
| `extract` | 逆向提取：从已有代码、旧页面或设计稿中提取设计模式、组件线索与内容结构（用于冷启动或迁移） |
| `shape` | 代码前规划：预先规划 UX 流程、信息架构与 UI 布局蓝图（不写代码，只出方案） |
| `craft` | 完整构建器：执行"规划→视觉迭代→代码生成"全流程，输出可直接运行的前端页面 |

# 检查与诊断（Audit & Review）

| 命令 | 作用 |
|------|------|
| `audit` | 技术质量扫描：检查性能、可访问性（a11y）、语法规范、依赖安全等工程指标 |
| `critique` | UX 设计评审：对交互与视觉进行专业设计审查，输出问题清单（常配合 `/design-taste-frontend` 组合使用） |
| `onboard` | 优先级引导：基于当前上下文 + 诊断结果，生成一份带优先级的优化行动方案（告诉你先修什么） |
| `polish` | 细粒度质量抛光：二次审计，对代码与视觉细节做最后的扫描润色（用于闭环复查） |

# 修复（Fix - 硬伤与缺陷）

| 命令 | 作用 |
|------|------|
| `clarify` | 文案修复：统一并修正界面上的文案、标签、占位符、微文案（保证语义清晰一致） |
| `adapt` | 设备适配修复：修复响应式断点、触摸交互、视口适配等跨设备显示问题 |
| `optimize` | 性能修复：解决加载耗时、渲染阻塞、资源体积过大等性能瓶颈 |

# 增强（Enhance - 视觉与体验）

| 命令 | 作用 |
|------|------|
| `typeset` | 字体排版：应用并完善字体层级、行高、字重节奏（奠定文字阅读基础） |
| `colorize` | 配色应用：注入或调整色彩方案，建立整体视觉基调与品牌色盘 |
| `layout` | 布局调整：优化栅格系统、间距、对齐方式，梳理页面空间结构 |
| `animate` | 动效注入：添加基础过渡、微交互、入场/出场动画（先搭运动骨架） |
| `bolder` | 视觉加码：增强关键区域（如 CTA、标题）的视觉冲击力与对比度 |
| `delight` | 愉悦细节：注入令人惊喜的细微反馈（如悬停彩蛋、状态切换的小趣味） |
| `overdrive` | 超常亮点：针对核心模块施加"超常规"的视觉强化（需克制使用，只打关键点） |

# 加固（Harden - 稳健与平衡）

| 命令 | 作用 |
|------|------|
| `harden` | 异常兜底：加强错误处理、边界情况、空状态、加载态（让页面在恶劣条件下也不崩溃） |
| `distill` | 信息提炼：精简视觉噪音，解决"乱、重、信息层级不清"的问题，让重点浮出水面 |
| `quieter` | 降噪平衡：降低上一轮增强带来的过度刺激或激进元素，恢复整体舒适度（给 `bolder`/`overdrive` 做对冲） |

# 文档同步（Documentation）

| 命令 | 作用 |
|------|------|
| `document` | 文档生成/同步：根据当前现有代码反向生成或更新 DESIGN.md，确保设计文档与代码实现始终对齐（应多次在检查阶段执行） |
